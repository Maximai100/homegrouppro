# Home Group — дорожная карта сайта

Сайт управляющей компании, которая сдаёт апартаменты в аренду: `homegrouppro.ru`.
Цель — современный сайт с моушен-дизайном и анимациями по скроллу, бронированием через Realty Calendar
и админкой с входом по паролю для текстов и объектов.

Обозначения: `[ ]` — не начато, `[~]` — в работе, `[x]` — готово, 🔴 — блокирует старт работ.
**Кто:** Claude — делаю я, Максим — нужно от тебя.

## Архитектура

```
                    VPS рег.ру (Ubuntu 24.04, 4 ГБ RAM, Docker Compose)
 посетитель ─HTTPS─▶ Caddy ─┬─▶ homegrouppro.ru         → Astro (SSR) ─┐
                            │      └─ /media/*  → файлы загрузок напрямую (долгий кеш)
                            ├─▶ dev.homegrouppro.ru     → Astro (SSR, черновики) ─┤ под паролем
                            └─▶ admin.homegrouppro.ru   → Payload CMS ◀───────────┘ (одна на прод и превью)
                                                              └─▶ PostgreSQL
   /api/lead (Astro) → заявка сохраняется в Payload → уведомление в Telegram (без персональных данных)
   Ночные бэкапы БД и загрузок → внешнее хранилище в РФ. Мониторинг — снаружи сервера.

 Код: GitHub → GitHub Actions собирает образы → реестр GHCR → VPS забирает образ и перезапускается
 Бронирование: виджет Realty Calendar (данные гостей и оплаты у Realty Calendar)
```

## Принятые решения

| Что | Решение | Почему |
|---|---|---|
| Хостинг | VPS на рег.ру, 4 ГБ RAM | Свой сервер в РФ. 2 ГБ не хватит: Payload + 2 Astro + PostgreSQL |
| Сервер | Ubuntu 24.04, Docker Compose, swap 2 ГБ | Всё описано в одном файле, легко переносить и откатывать |
| Сборка | Образы собирает GitHub Actions, на VPS только запуск | Сборка Payload (Next.js) требует много памяти, VPS её не потянет |
| Веб-сервер | Caddy | Автоматический HTTPS, HTTP/2–3, раздача загрузок и кадров с долгим кешем |
| Каркас | Astro + TypeScript, серверный режим (Node) | Контент из админки появляется на сайте сразу, без пересборки |
| Устойчивость | Astro кеширует ответы Payload и при его сбое отдаёт последнюю версию | Падение админки не роняет сайт |
| Админка | Payload CMS на `admin.homegrouppro.ru`, **один экземпляр** для прода и превью | Контент вводится один раз и сразу в бою; превью показывает черновики |
| Изменения структуры | Миграции Payload (`migrate:create` → проверка на копии базы → `migrate` при деплое) | Без них новые поля на проде ломают базу |
| База | PostgreSQL (`@payloadcms/db-postgres`) | Надёжно, бэкапы через `pg_dump` |
| Редакторы | Максим — администратор, менеджер — редактор | — |
| Стили | CSS с переменными из дизайн-системы | Предсказуемо, без лишних зависимостей |
| Дизайн | Claude Design: Design System + Design (макеты) | Утверждаем вид до кода, токены переносятся в CSS 1:1 |
| Шрифты | Только с полной кириллицей, свои файлы на сервере | Многие модные шрифты без кириллицы; Google Fonts = передача IP за рубеж |
| Моушен | GSAP + ScrollTrigger + SplitText | Закрепление секций, scrub, появление заголовков |
| Плавный скролл | Lenis только на десктопе | На тач-экранах инерция мешает |
| Простые появления | CSS `animation-timeline: view()` с фолбэком | Без JS там, где он не нужен |
| Киношные сцены | Ролики Higgsfield → кадры → Canvas, 2–3 сцены. План Б — параллакс фото | Плавный scrub на iOS; если генерация не удастся, сайт не встаёт |
| Схема бухты | Стилизованный SVG по данным OpenStreetMap (с указанием источника) + GSAP | Точная география, законная основа, лёгкая и кликабельная |
| Бронирование | Виджет Realty Calendar, ленивая загрузка | Цены и календарь живут там, не дублируем |
| Связь с Realty Calendar | Уровень 1: объект заводится в Realty Calendar, в админке — карточка с его ID. Без API | Realty Calendar — главный источник; API — позже, если дадут доступ |
| Заявки собственников | Форма → `/api/lead` → **сначала** запись в Payload → уведомление в Telegram без имени и телефона | Персональные данные остаются в РФ, нет трансграничной передачи |
| Превью | `dev.homegrouppro.ru` под паролем, `noindex` | Смотреть с iPhone, не трогая заглушку |
| Аналитика | Яндекс Метрика, Вебвизор с маскировкой полей форм | Российская аудитория; не записываем телефоны в Вебвизор |
| Почта | Почта на домене (`info@homegrouppro.ru`) для сброса паролей и контактов | Письма с домена не попадают в спам (SPF, DKIM) |
| Тесты | Короткие e2e-проверки (Playwright) в GitHub Actions перед каждым деплоем | Форма, кнопка бронирования и страницы не ломаются незаметно |
| Не используем | Next.js для сайта (он есть только внутри Payload), Motion, Three.js/R3F, Vercel, Spline, Yandex Cloud Functions, Git-CMS, Directus | Не нужны в этой схеме |

**Правило веток:** до запуска заглушка живёт на GitHub Pages из `main`, поэтому всё, что лежит в `main`,
видно на домене. Разработка идёт в ветке `dev`. После переключения домена на VPS (фаза 11) GitHub Pages
отключаем, и `main` становится веткой продакшена.

**Правило про видео:** нарезка и обработка роликов идёт по навыку `video-pipeline` с QA-гейтом.
Исходные ролики в Git не кладём: они хранятся у Максима и в бэкапе, в Git — только готовые кадры.

**Правило про секреты:** пароли, токен Telegram-бота и ключи лежат только в `.env` на сервере и в менеджере
паролей Максима. В Git и в переписку они не попадают, на сервер их вносит Максим по инструкции.

| [Belgrade Arbor](https://belgradearbor.rs/en) | Анимированный «хвост» за курсором |
| [Faith Ibiza](https://faithibiza.com) | Квадратные и прямоугольные вставки с видео, разбросанные по странице коллажем, с крупными подписями |

Не берём: 3D-модели (Belgrade Arbor), горный и зимний антураж (Hotel Royal). Антипример — Sobha Privy
Collection: требует повернуть телефон.

**Что это меняет в сайте:**
- **Видео становится основным материалом,** а не только 2–3 сцены по скроллу. Добавляются короткие зацикленные
  ролики без звука: фон первого экрана и видеовставки в разделах. Их тоже генерируем в Higgsfield или снимаем.
- **Хвост за курсором** — только на десктопе, отключается при `prefers-reduced-motion`.

## Порядок работ

Три потока идут параллельно, чтобы ожидание одного не останавливало остальные:

```
ШАГ 1 — рабочий сайт
  Поток A (сайт):    1 Структура → 1.5 Дизайн → 3 Каркас → 5 Вёрстка → 8а Лёгкий моушен ─┐
  Поток B (сервер):  2 Сервер → 4 Админка → 6 Интеграции → 10 Деплой ────────────────────┤
                                                                9 Качество → 11 Запуск → 12 Передача
  Поток C (видео):   промпты из фазы 1 → Максим генерирует → 7 Кадры  (идёт параллельно шагу 1)
                                                                   ↓
ШАГ 2 — киношные сцены (через 2–4 недели после запуска)
                     8б Видеосцены → 9 Качество повторно → 13 Выкладка шага 2
```

Самый длинный путь — входные данные от Максима (бренд, фото, тезисы) и генерация видео.
Поэтому промпты для Higgsfield выдаю сразу после утверждения сценария, а не в конце.

**Запуск в два шага** (решение Максима):
- **Шаг 1 — рабочий сайт.** Все страницы, объекты, схема бухты, бронирование, форма собственников, админка,
  лёгкий моушен (появление текстов, параллакс фото, переход к схеме, микровзаимодействия, плавный скролл).
  На местах будущих киношных сцен — план Б: параллакс реальных фото. Сайт сразу начинает приносить заявки.
- **Шаг 2 — киношные сцены, через 2–4 недели после запуска.** Сцены из роликов Higgsfield заменяют
  план Б по одной, без простоя сайта. Генерация роликов идёт параллельно шагу 1, а не после него.
- Вёрстка мест под сцены в шаге 1 сразу делается с учётом шага 2 (те же размеры и пины), чтобы потом
  менять только содержимое, а не макет.
